## Tauri config voor Windows

In `src-tauri/tauri.conf.json`: voeg Windows bundle-targets toe. Niet alle drie tegelijk — kies één:
- **MSI via WiX** (Tauri default, robuust, vereist WiX Toolset 3.x)
- **NSIS** (lichter, sneller iteratie, default in Tauri 2.x)
- **MSIX** (Microsoft Store-compatible, later wanneer Store-strategy duidelijk is)

Mijn advies: start met NSIS. Snelste feedback-loop. MSI later voor enterprise distributie.

## Code-signing Windows

Geen EV cert op dit moment. Opties:
1. **Azure Trusted Signing** (Microsoft's nieuwe cloud signing — ~10 EUR/maand, geen hardware token)
2. **EV Certificate** (eenmalig 300-500 EUR, hardware token of cloud HSM)
3. **Self-signed voor dev/beta** (SmartScreen waarschuwt gebruikers — alleen tijdelijk)

Begin met optie 3 voor lokale builds. Optie 1 of 2 is Christians keuze, niet de jouwe. Stel voor, hij beslist.

## Auth-context — niet jouw zorg, maar weet het

Per 2026-05-25 is `web/` gemigreerd van `@neondatabase/auth` (Neon Auth managed) naar self-hosted **Better Auth** (`auth.*` schema in dezelfde Neon-database, Resend voor NL email-templates).

**Voor jou (Tauri Windows):** dit raakt je niet. De desktop-app heeft geen user-session — `managers/license.rs` praat met `/api/license/activate` (code→token) en `/api/license/status` (Bearer license-token). Dat is een **license-token**, niet een Better Auth session-token. Geen cookies, geen redirects, geen OAuth.
